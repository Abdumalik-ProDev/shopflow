## Data separation (per VISION.md §5)

- **`ml/data/raw/olist/`** → Historical Olist data for ML training only. Symlinked to `../../dataset`. Never treated as live inventory.
- **`ml/data/cleared/`** → Processed, model-ready feature CSVs generated by `02_feature_engineering.ipynb`.
- **Live marketplace data** → Stored in PostgreSQL (backend), populated by `backend/scripts/seed_olist.py`.

## ML engineering principles (per VISION.md §4)

- Training, experimentation, inference, and business integration remain distinct.
- Models accept validated features and return predictions; they know nothing about HTTP or React.
- The application layer integrates ML capabilities into order management via APIs (`/recommendations`, `/analytics`).
- Reproducible experiments, feature pipelines, temporal validation, hyperparameter tuning, model evaluation, explainability, versioning, and inference.
- Primary dataset: Brazilian Olist e-commerce dataset.

## Running

```bash
# Install ML dependencies
cd ml
pip install -r requirements.txt   # or: uv sync

# Start MLflow (via Docker Compose or standalone)
docker compose -f docker/docker-compose.yml up mlflow

# Run all training pipelines
python -m training.train_all

# Or launch Jupyter for exploration
jupyter lab notebooks/
```
